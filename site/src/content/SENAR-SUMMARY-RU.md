# SENAR — Supervised Engineering & Normative AI Regulation

Первая формализованная методология для AI-нативной разработки ПО.
Версия 1.3 | 25.03.2026 | Авторы: Андрей Юмашев, Вадим Соглаев | senar.tech

## В одном предложении

SENAR определяет, как Супервайзеры управляют AI-агентами для производства верифицированного, отслеживаемого программного обеспечения с гарантией качества.

## Сдвиг парадигмы

AI — уже не ассистент, а основной производитель кода. Роль человека меняется: от написания кода к надзору за AI — проектирование контекста, верификация результатов, архитектурные решения, контроль качества.

## 5 ценностей

1. **Контекст важнее кода** — качество результата AI определяется качеством входного контекста
2. **Верификация важнее скорости** — ограничение — корректность, а не скорость
3. **Знание важнее опыта** — что не задокументировано, не существует для AI
4. **Принуждение важнее договорённостей** — шлюзы качества как автоматический контроль, а не совещания
5. **Суждение важнее нажатий клавиш** — внимание человека на решения, а не на набор текста

## SENAR Core (8 правил)

Точка входа для индивидуальных разработчиков: 8 правил, 2 шлюза качества (Стартовый шлюз + Финишный шлюз), 2 метрики (FPSR + Dead End Rate), чеклист верификации из 28 пунктов по 3 уровням (Standard / High / Critical). Специальный инструментарий не требуется.

## Структура (Standard)

- **5 ролей:** Супервайзер, Контекстный архитектор, Инженер знаний, Менеджер потока, Инженер верификации
- **4 единицы работы:** Исследование → Задача → Сессия → Инкремент
- **5 шлюзов качества:** QG-0 (Контекст) → QG-1 (Требования) → QG-2 (Реализация) → QG-3 (Верификация) → QG-4 (Приёмка)
- **10 метрик:** Пропускная способность, Время выполнения, FPSR, DER, KCR, Предсказуемость стоимости, Стоимость задачи, MIR, Время цикла, ADR
- **15 правил:** задача перед работой, длительность сессии, контрольные точки, тупики, аудиты, версионный контроль, лимит параллельных агентов, калибровка стоимости, захват знаний, трассировка требований, документация кода, гигиена контекста, управление AI-моделями, управление скриптами, верификация качества AI-вывода
- **4 конфигурации:** Базовая (Core, 1 пара) → Начальная (Foundation, 1–3) → Командная (Team, 3–10) → Корпоративная (Enterprise, 10+)
- **5 уровней зрелости:** Стихийный → Супервизируемый → Измеримый → Управляемый → Оптимизирующий
- **Инструментирование агентов:** уровни контроля, профили агентов, управление скриптами, структурированный протокол инструментов, изоляция диспетчеризации, федерация

## Чеклист верификации — 28 пунктов (3 уровня)

- **Standard** (10 пунктов, каждая задача): область изменений, удаления, фантомные зависимости, качество тестов, подмена тестов, валидация ввода, захардкоженные секреты, устаревшие паттерны, кросс-файловая консистентность, качество кода
- **High** (ещё 8 пунктов, задачи безопасности): обход null-guard, обход пустого конфига, доверие заголовкам, IDOR, шорткат return-True, покрытие авторизацией, небезопасная десериализация, SSRF
- **Critical** (ещё 10 пунктов, сложные/регуляторные): версии зависимостей, захардкоженные значения, переусложнение, дублирование, крайние случаи, именование, область коммита, инъекция через форматирование строк, недостижимый защитный код, проглоченные исключения

## Ключевые инновации

- **Пара Супервайзер+AI** как единица производства (заменяет команду разработки)
- **First-Pass Success Rate** — измеряет качество контекста, не скорость кодирования
- **Документирование тупиков** — обязательно (порог >15 мин), не даёт AI повторять ошибки
- **Шлюзы качества как код** — автоматический контроль стандартов, а не ручные чеклисты
- **Adversarial Detection Rate** — измеряет плотность скрытых дефектов в AI-выводе
- **Инструментирование агентов** — уровни контроля, профили, изоляция диспетчеризации, федерация
- **Чеклист верификации (28 пунктов)** — 3-уровневое ревью AI-кода по уровню риска
